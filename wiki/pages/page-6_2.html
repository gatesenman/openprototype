Design Rules Engine & Audit

Relevant source files The following files were used as context for generating this wiki page: - [src/__tests__/core.test.ts](https://github.com/gaosichun888/openprototype/blob/main/src/__tests__/core.test.ts) - [src/designsystem/audit.ts](https://github.com/gaosichun888/openprototype/blob/main/src/designsystem/audit.ts) - [src/designsystem/rules.ts](https://github.com/gaosichun888/openprototype/blob/main/src/designsystem/rules.ts) - [src/interop/importDesign.ts](https://github.com/gaosichun888/openprototype/blob/main/src/interop/importDesign.ts) - [src/schema/layout.ts](https://github.com/gaosichun888/openprototype/blob/main/src/schema/layout.ts)

The Design Rules Engine and Audit system provides a validation and correction layer for the OpenPrototype design environment. It ensures that generated or manually edited designs adhere to the semantic constraints of the DesignSystem and meet accessibility standards. This subsystem acts as a bridge between high-level design intent (e.g., "use the primary color") and the concrete properties of nodes on the canvas.

Design Rules Engine

The Rules Engine is responsible for the automated enforcement of design consistency. It operates primarily through the applyRules function, which traverses a frame's node hierarchy and applies corrective logic based on the active DesignSystem.rules.

DesignRule Types

Rules are defined as objects within the DesignSystem and typically fall into three categories: - primary-button-token: Enforces that any node identified as a "button" uses the primary color token for its fill src/designsystem/rules.ts:23-35. - card-radius: Synchronizes the radius property of rectangles and images with a global design system value src/designsystem/rules.ts:36-51. - min-tap-target: An accessibility rule that ensures interactive elements (buttons, inputs) meet a minimum height requirement (e.g., 40px or 44px) src/designsystem/rules.ts:52-62.

Auto-fix Pipeline

The applyRules function implements an auto-fix pipeline. When the AI generates a new frame or a user modifies a component, the system runs this pipeline to ensure compliance.

Design System Audit

While the Rules Engine fixes specific nodes, the Audit system evaluates the health and completeness of the DesignSystem itself. It is designed to act as a "Senior PM / Designer" check src/designsystem/audit.ts:29-33.

AuditFinding Levels

Findings are categorized into three levels: - ok: Requirement met or best practice followed. - warn: Minor inconsistency or missing non-critical scale (e.g., missing elevation levels). - error: Critical deficiency (e.g., missing mandatory semantic colors).

Integration with AI Generation

Design rules are deeply integrated into the AI generation workflow to ensure that the output of Large Language Models (LLMs) or local heuristics is immediately usable and on-brand.

  1. Local Generation: The generateFrameFromMarkdown utility uses the DesignSystem to map generic element names (like "Login Button") to specific node types and default tokenized styles src/tests/core.test.ts:59-70.
  2. Post-Processing: Immediately after a frame is generated by the AI (via generatePage or generateFlow), applyRules is called to "clean up" the output, ensuring all buttons use the primary token and interactive elements are large enough for touch src/designsystem/rules.ts:14-17.
  3. Token Binding: During the fixNode process, hardcoded hex values are replaced with token references (e.g., { type: "token", token: "primary" }), which ensures that if the design system tokens are updated later, the AI-generated screens update automatically src/designsystem/rules.ts:27.

Implementation Details

Node Traversal

The applyRules function uses a recursive fixNode inner function to ensure that rules are applied to nested children within groups or frames src/designsystem/rules.ts:20-66.

Rule Customization

Rules are not hardcoded; they respect the value field within the DesignRule object. For example, if a user updates the card-radius rule in the DesignSystem to 12, subsequent calls to applyRules will automatically adjust rectangles to 12px src/tests/core.test.ts:104-125.
